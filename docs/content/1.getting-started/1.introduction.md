## What it is

Imagine a **multi-tenant school management system**, where each district has its own schools, classes, teachers, and students. A test that checks whether a class is full may first need to create a district, a school, a class, a teacher, and several students, all linked to the correct tenant.

Setting up their IDs, required fields, relationships, and timestamps can take dozens of lines before the assertion. Repeating that setup creates long tests and makes the behavior under test harder to spot. For coding agents, those routine details also fill the context space with values unrelated to the task. Reusable defaults let both the reader and the agent focus on what this test needs to prove.

Zeeq Biome brings those choices into reusable blueprints. A **biome** is your app's entity graph in miniature: just the rows one test needs, wired together correctly. The library targets `.NET 10` / `C# 14`.

- You declare a **blueprint** for each entity type, with valid defaults that most tests can leave alone.
- A test uses a short fluent chain to describe its scenario and set the properties it depends on.
- Parents and children are typed, numbers and ordering come from sequences, the clock is controlled, and persistence is pluggable (EF Core or none).

::tip
When setup repeats every default, the reader has to guess which values matter. **Customize only the property under test** so the setup points to the behavior you want to check.
::

## The payoff

A test needs an active code-review lock. Here is the setup against zeeq-app's real model shapes, written with and without Biome:

::code-group

```csharp [With Biome] {1}
await TestBiome.Start(_db, out _).AddLockedReview(out var activeLock).BuildAsync();
_db.ChangeTracker.Clear();
```

::code-collapse{label="Without Biome" name="setup"}
```csharp
var seed = ZeeqSeed.Generate();
var now = DateTimeOffset.UtcNow;
// match Postgres precision
now = new DateTimeOffset(now.Ticks - now.Ticks % 10, TimeSpan.Zero);

var repo = new CodeRepository
{
    Id = $"repo_{Guid.CreateVersion7():N}",
    OrganizationId = seed.Organization.Id,
    Provider = "github",
    OwnerQualifiedName = "zeeq-ai/example",
    DisplayName = "zeeq-ai/example",
    Enabled = true,
    CreatedAtUtc = now,
    UpdatedAtUtc = now,
};
var pr = new PullRequestRecord
{
    Id = $"pr_{Guid.CreateVersion7():N}",
    OrganizationId = repo.OrganizationId,
    RepositoryId = repo.Id,
    OwnerQualifiedRepoName = repo.OwnerQualifiedName,
    PullRequestNumber = 1,
    GitHubNodeId = "PR_1",
    Title = "Pull request 1",
    Branch = "feature/1",
    BaseBranch = "main",
    HeadSha = Guid.CreateVersion7().ToString("N"),
    AuthorLogin = "octocat",
    HtmlUrl = "https://github.com/zeeq-ai/example/pull/1",
    State = PullRequestState.Open,
    CreatedAtUtc = now,
    CreatedFromWebhookAtUtc = now,
    LastWebhookAtUtc = now,
    UpdatedAtUtc = now,
};
var review = new CodeReviewRecord
{
    Id = $"cr_{Guid.CreateVersion7():N}",
    OrganizationId = pr.OrganizationId,
    PullRequestRecordId = pr.Id,
    RepositoryId = repo.Id,
    OwnerQualifiedRepoName = repo.OwnerQualifiedName,
    PullRequestNumber = pr.PullRequestNumber,
    Branch = pr.Branch,
    Title = pr.Title,
    AuthorLogin = pr.AuthorLogin,
    Status = CodeReviewStatus.Pending,
    CreatedAtUtc = now,
    UpdatedAtUtc = now,
};
var activeLock = new ActiveCodeReviewLock
{
    OrganizationId = review.OrganizationId,
    RepositoryId = repo.Id,
    PullRequestRecordId = pr.Id,
    PullRequestCreatedAtUtc = pr.CreatedAtUtc,
    CodeReviewRecordId = review.Id,
    CodeReviewCreatedAtUtc = review.CreatedAtUtc,
    Status = review.Status,
    AcquiredAtUtc = now,
    ExpiresAtUtc = now.AddMinutes(5),
    UpdatedAtUtc = now,

_db.AddRange(seed.Owner, seed.Organization, repo, pr, review, activeLock);
await _db.SaveChangesAsync();
_db.ChangeTracker.Clear();
```

## Why "biome"

The name reflects the idea of a small, self-consistent environment. A useful test fixture contains the entities that interact in this scenario, with valid relationships between them. That idea carries through the vocabulary:

|Term|Meaning|
|---|---|
|**Seed**|The baseline every test starts from: an owner, an organization, whatever your app always needs.|
|**Blueprint**|The recipe for one entity type: a factory plus optional traits and derived defaults.|
|**Sequence**|A declared-once counter or rank, scoped per session, parent or ancestor.|
|**Anchor**|The typed parent the next Add attaches to. Every Add re-anchors to its own output.|
|**Store**|Where the finished biome is saved: EF Core, none, or your own `IBiomeStore`.|

## The one rule

Defaults make setup shorter, but they should not undo the value a test chose. Biome runs customizers before derived and global defaults, which fill only unset properties. **The test's chosen value takes precedence over those defaults.** See [Customizing](/guides/customizing) for the order and what counts as unset.

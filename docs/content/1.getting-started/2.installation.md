Biome can work with the test framework you already use. Start with the core package; add the EF Core integration if your tests need to persist the graph.

## Requirements

- Starting with **version 1.2.0**, both packages target **.NET 8, .NET 9, .NET 10, and .NET 11**.
- **C# 14** to consume core extension-block APIs, including APIs called by generated graft methods. The .NET 10 SDK / Roslyn 5 is the minimum consumer toolchain for targets .NET 8 through 10; use .NET 11 SDK / C# 15 for a `net11.0` project. Build this repository with SDK **11.0.100 / C# 15**. Generated graft methods are regular extension methods.
- Any test framework. The examples use [TUnit](https://tunit.dev).
- The core package has **no dependencies**.

The EF integration selects the matching EF Core major with these minimum versions:

| Target framework | EF Core minimum |
|---|---:|
| .NET 8 | 8.0.11 |
| .NET 9 | 9.0.0 |
| .NET 10 | 10.0.0 |
| .NET 11 | 11.0.0 |

Some seed examples use `Guid.CreateVersion7`, which requires .NET 9 or later. On .NET 8, use your app's UUIDv7 helper for seed IDs. Blueprint factories can use `ctx.NewId` on all four targets.

::tip
Point agents at <https://zeeq-ai.github.io/zeeq-biome/llms.txt> and <https://zeeq-ai.github.io/raw/reference/api-cheat-sheet.md> to quickly refactor your existing tests and see 25-50% reduction in your test code LoC.
::

## Add the packages

For manual setup, add the packages based on whether you need unit tests or integration tests:

::code-group

```bash [dotnet CLI] {1-4}
# Start with the core package for in-memory setup.
dotnet add package Zeeq.Biome
# Add this package if tests save through a DbContext.
dotnet add package Zeeq.Biome.EntityFrameworkCore
```

```xml [Tests.csproj] {7-10}
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <LangVersion>14.0</LangVersion>
  </PropertyGroup>
  <ItemGroup>
    <!-- The core package builds test graphs in memory. -->
    <PackageReference Include="Zeeq.Biome" Version="*" />
    <!-- Include the EF Core adapter when tests save the graph. -->
    <PackageReference Include="Zeeq.Biome.EntityFrameworkCore" Version="*" />
  </ItemGroup>
</Project>
```

Change `TargetFramework` to `net9.0`, `net10.0`, or `net11.0` when that is your project target. Use SDK 10 or later and C# 14 or later; `net11.0` requires SDK 11.

```xml [Directory.Packages.props] {3-5}
<Project>
  <ItemGroup>
    <!-- Pin both packages here when using Central Package Management. -->
    <PackageVersion Include="Zeeq.Biome" Version="x.y.z" />
    <PackageVersion Include="Zeeq.Biome.EntityFrameworkCore" Version="x.y.z" />
  </ItemGroup>
</Project>
```

::

::note
Only add `Zeeq.Biome.EntityFrameworkCore` when you want to **save through a `DbContext`**. For pure unit tests, the core package alone is enough.
::

## Input blueprint API version

Ordinary entity outputs for `Blueprint.FromInput`, and `Blueprint.ChildFromInput`, are available in `Zeeq.Biome` 1.1.0 and later. If you also use `Zeeq.Biome.EntityFrameworkCore`, use the matching package version. See [Input blueprints](/guides/input-blueprints) for their behavior.

## Namespaces


## Verify the install

To check the install before defining your app's blueprints, start a small session in a test. This example needs no store:

```csharp [InstallTests.cs] {6-8}
public sealed class InstallTests
{
    [Test]
    public async Task Biome_starts()
    {
        // With no store, the session can build without a database.
        var biome = Biome.Start("America/Chicago", new BiomeOptions<string>());
        await biome.BuildAsync();
    }
}
```

::tip
The minimal install above uses the school district's time zone as a plain `string` seed. The [Quick start](/getting-started/quick-start) puts that value in a record and wraps the entry point in `TestBiome`.
::

A fulfilment test may need several orders and shipments, with numbering shared at different levels. This example separates those scopes and keeps checkout inputs unsaved so the code under test can process them.

`Customer` → `Order` → `LineItem` → `Shipment` → `TrackingEvent`, plus a transient `CheckoutInput` that models a request DTO. Each level numbers itself with a **different scope**. Source: [`tests/Zeeq.Biome.Tests/Commerce`](https://github.com/zeeq-ai/zeeq-biome/tree/main/tests/Zeeq.Biome.Tests/Commerce).

Every scenario exists twice in one `CommerceTests` partial class: `CommerceTests.WithBiome.cs` uses Biome, and `CommerceTests.Typical.cs` sets up the same entities by hand with identical assertions. Read them side by side to see what Biome removes.

## One seed, four scopes

|Sequence|Scope|Reads as|
|---|---|---|
|`OrderNumbers`|`.Per<Customer>()`|orders count up across a customer's whole history|
|`LineNumbers`|`.PerParent()`|each order starts its own line numbering|
|`ShipmentNumbers`|`.Per<Customer>()`|shipment numbers span all lines and orders for the customer|
|`EventNumbers`|`.PerParent()`|a shipment's checkpoints are ordered independently|

```csharp [Commerce/Domain.cs] {1-4,11-13,21-22,26-28}
// Number parcels across the customer's orders so a new line keeps the same sequence.
internal static readonly Sequence<int> ShipmentNumbers = Sequence
    .Of(1, n => n + 1)
    .Per<Customer>();

internal static readonly ChildBlueprint<CommerceSeed, Customer, Order> Order = Blueprint
    .ChildOf<CommerceSeed, Customer, Order>(
        (customer, ctx) =>
            new() { Customer = customer, PlacedAt = ctx.Ago(TimeSpan.FromDays(2)) }
    )
    // Fill the number after customization so the reference uses the final number.
    .Derive(o => o.Number, OrderNumbers)
    .Derive(o => o.Reference, (o, _) => $"ORDER-{o.Number}");

internal static readonly ChildBlueprint<CommerceSeed, LineItem, Shipment> Shipment = Blueprint
    .ChildOf<CommerceSeed, LineItem, Shipment>(
        (line, ctx) =>
            new()
            {
                Line = line,
                // Follow the parent chain to link the customer that owns this shipment.
                Customer = ctx.Ancestor<Customer>(),
                ExpectedAt = ctx.FromNow(TimeSpan.FromDays(1)),
            }
    )
    // Use the customer-wide number so parcel labels continue across orders.
    .Derive(s => s.CustomerNumber, ShipmentNumbers)
    .Derive(s => s.Label, (s, _) => $"PARCEL-{s.CustomerNumber}");
```

## A busy store in one chain

Counts are **per parent**, so each line multiplies the previous output: 2 customers × 3 orders × 4 lines × 1 shipment × 3 events.

::code-group

```csharp [With Biome] {4-12}
var biome = TestBiome.Start(out _, store);

await biome
    // Each child count applies to every parent in the previous step.
    .AddCustomers(out var customers, 2)
    .AddOrders(out var orders, 3)
    .AddLineItems(out var lines, 4)
    .AddShipments(out var shipments, 1)
    .AddTrackingEvents(out var events, 3)
    // Return to the orders to attach one in-memory request to each.
    .Under(orders)
    .AddCheckoutInputs(out var inputs, 1)
    .BuildAsync();
```

::code-collapse{label="Without Biome" name="setup"}
```csharp
var customers = Enumerable
    .Range(0, 2)
    .Select(_ => new Customer { Name = "Example shop shopper" })
    .ToArray();
var now = DateTimeOffset.UtcNow;

var orders = new List<Order>();
var lines = new List<LineItem>();
var shipments = new List<Shipment>();
var events = new List<TrackingEvent>();
foreach (var customer in customers)
{
    // Reset both counters at the customer boundary so they span that customer's orders.
    var orderNumber = 1;
    var shipmentNumber = 1;
    for (var o = 0; o < 3; o++)
    {
        var order = new Order
        {
            Customer = customer,
            Number = orderNumber,
            Reference = $"ORDER-{orderNumber}",
            PlacedAt = now.AddDays(-2),
        };
        orderNumber++;
        orders.Add(order);
        for (var l = 0; l < 4; l++)
        {
            var line = new LineItem
            {
                Order = order,
                Number = l + 1,
                Sku = $"SKU-{l + 1}",
            };
            lines.Add(line);
            var shipment = new Shipment
            {
                Line = line,
                Customer = customer,
                CustomerNumber = shipmentNumber,
                Label = $"PARCEL-{shipmentNumber}",
                ExpectedAt = now.AddDays(1),
            };
            shipmentNumber++;
            shipments.Add(shipment);
            for (var e = 0; e < 3; e++)
            {
                events.Add(
                    new TrackingEvent
                    {
                        Shipment = shipment,
                        Customer = customer,
                        Number = e + 1,
                        Description = $"Checkpoint {e + 1}",
                        OccurredAt = now.AddHours(-24) + TimeSpan.FromMinutes(e + 1),
                    }
                );
            }
        }
    }
}

// Keep the requests in memory for checkout while the fulfillment rows go to the store.
var inputs = orders
    .Select(order => new CheckoutInput { Order = order, Reference = order.Reference })
    .ToArray();

db.AddRange(customers);
db.AddRange(orders);
db.AddRange(lines);
db.AddRange(shipments);
db.AddRange(events);
await db.SaveChangesAsync();
```
::

::

::note
This setup uses **one chain** at the call site. The numbering rules remain visible in the blueprints: parcels count per customer, SKUs per order, and events within each shipment. Tests can reuse those choices without managing the counters themselves.
::

Assertions the real test makes: `biome.All<Order>().Count == 6`, `lines[4].Number == 1` (a new order restarts), `shipments[4].CustomerNumber == 5` (spans orders), `shipments[12].CustomerNumber == 1` (a new customer restarts), and the store holds `2 + 6 + 24 + 24 + 72` rows, **no** `CheckoutInput`.

## Transient request inputs

`CheckoutInput` is built next to the stored entities but never saved. `AsTransient()` lives on the blueprint, so every use is excluded:

```csharp [Commerce/Domain.cs] {4-5}
internal static readonly ChildBlueprint<CommerceSeed, Order, CheckoutInput> Checkout = Blueprint
    .ChildOf<CommerceSeed, Order, CheckoutInput>((order, _) => new() { Order = order })
    .Derive(i => i.Reference, (i, _) => i.Order.Reference)
    // Keep each request available for checkout without inserting it.
    .AsTransient();
```

## Traits, explicit numbers, resuming a customer

`+` makes one order cancelled **and** priority; the comma makes another. The explicit `Number = 1` is skipped by the generator, so the first order becomes `2`, and `.Under(customer)` resumes the customer's sequence.

```csharp [CommerceTests.WithBiome.cs] {3-4,8-10}
await biome
    .AddCustomer(out var customer)
    // Combine traits on one order and reserve number 1 on the other so the first takes 2.
    .AddOrders(out var orders, Orders.Cancelled + Orders.Priority, o => o.Number = 1)
    .AddLineItems(out var lines, 2)
    .AddShipments(out var shipments, 1)
    .AddTrackingEvents(out _, 2)
    // Return to the customer so the next order takes number 3.
    .Under(customer)
    .AddOrder(out var next)
    .BuildAsync();

// orders[0].Number == 2 ("ORDER-2"), orders[1].Number == 1, next.Number == 3
// lines[2].Number == 1 (local reset)
// shipments[2].CustomerNumber == 3 (customer-wide)
```

## A helper for the deep default branch

```csharp [Commerce/ScenarioHelpers.cs] {8-13}
public static class CommerceScenarioHelpers
{
    extension(BiomeBuilder<CommerceSeed, CommerceSeed> b)
    {
        public BiomeBuilder<CommerceSeed, TrackingEvent[]> AddTrackedOrder(
            out TrackingEvent leaf
        ) =>
            // Return the checkpoint so the test can revisit its shipment later.
            b.AddCustomer(out _)
                .AddOrder(out _)
                .AddLineItem(out _)
                .AddShipment(out _)
                .AddTrackingEvent(out leaf);
    }
}
```

The helper pairs with a shared clock to add a **later** checkpoint, as shown in [Time and precision](/guides/time-and-precision#a-live-clock-between-adds).

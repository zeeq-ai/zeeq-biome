The easiest way to choose a pattern is to see it in a scenario that resembles your own. These examples cover eight small domains in `tests/Zeeq.Biome.Tests`, each with a seed, blueprints, scenario chains, and tests that run in CI.

Start with the domain closest to your app. Each page highlights the choices that matter and compares the setup with a hand-written version, so you can see what moves into the blueprints.

|Domain|Seed|Shows|
|---|---|---|
|[CodeReviews](/examples/code-reviews)|org + owner|re-anchoring, `ctx.Ancestor`, `.Per<T>` sequence, helper, time|

::tip
The same layout works in your app: one folder per area, with `Blueprints.cs` (annotated with `[BiomeGraft]`), optional `Traits.cs`, `ContextExtensions.cs` for repeated context overloads, and `ScenarioHelpers.cs` for named multi-step chains. See [Generated grafts and scenario helpers](/guides/scenario-helpers-and-sugar#where-to-put-things).
::

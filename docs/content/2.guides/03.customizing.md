## The one rule

::note
***The call site wins, then the more specific default. Nothing overwrites.***
::

For every entity in an Add step, Biome runs the same pipeline, in this order:

1. **Factory** creates the entity. IDs are set here with `ctx.NewId`.
2. **Traits** (`.With`) run, in declaration order.
3. **Call-site customizers** run.
4. **`Derive`s** run, fill-only and in declaration order. Sequences first reserve every explicit value in the step, then fill the rest.
5. **Global defaults** (`options.Default`) run, fill-only.
6. The entity is recorded, with its parent link and step.

There is no `OnCreated` hook that can overwrite a value. Steps 4 and 5 only fill properties that are still unset.

## Traits: comma makes a new entity, plus stacks

A **trait** is a named `Action<T>` value, so you can pass it anywhere a customizer goes.

```csharp [Repositories.cs]
public static class Repositories
{
    public static readonly Action<CodeRepository> Disabled = r => r.Enabled = false;
    public static readonly Action<CodeRepository> Hidden = r => r.VisibleInLibraryPicker = false;
}
```

```csharp [Traits in a chain] {3-4}
await TestBiome.Start(out _)
    .Add(Blueprints.Repository, out var repos,
        Repositories.Disabled,                        // repos[0]: disabled
        Repositories.Disabled + Repositories.Hidden)  // repos[1]: disabled and hidden
    .BuildAsync();
```

::note
**A comma makes a new entity. `+` stacks traits on the same entity.** The tests in `CodeReviews` show the same idea: `PullRequests.Closed + PullRequests.Merged` is one pull request, while `PullRequests.Closed, PullRequests.Merged` is two.
::

Bake a trait into a **variant** with `.With`. The base blueprint is not changed:

```csharp [Blueprints.cs] {2}
public static readonly Blueprint<ZeeqSeed, CodeRepository> DisabledRepository =
    Repository.With(Repositories.Disabled);
```

## Context-aware customizers

A customizer that needs the context takes **two parameters**:

```csharp [Relative time] {3-4}
await TestBiome.Start(out _)
    .AddCodeRepository(out _)
    .AddOne(Blueprints.Repository, out var old,
        (r, ctx) => r.CreatedAtUtc = ctx.Ago(TimeSpan.FromDays(30)))
    .BuildAsync();
```

::warning
C# cannot mix one-parameter and two-parameter lambdas in a single call. When you mix them, write **all** of them in the two-parameter form. The sugar methods accept only `Action<T>`, so a context-aware customizer goes through the core `Add` / `AddOne`.
::

## Derived defaults are fill-only

`.Derive` assigns a property only if it **still has its default value** after the traits and customizers have run. A value the test set is never overwritten.

```csharp [Blueprints.cs] {11}
public static readonly Blueprint<ZeeqSeed, OrganizationMembership> PendingInvitation =
    Blueprint.For<ZeeqSeed, OrganizationMembership>(ctx => new()
        {
            Id = ctx.NewId("mem"),
            OrganizationId = ctx.Seed.Organization.Id,
            Status = MembershipStatus.Pending,
            InvitedEmail = "invited@example.test",
            CreatedByUserId = ctx.Seed.Owner.Id,
            CreatedAtUtc = ctx.Now,
        })
        .Derive(m => m.ExpiresAtUtc, (m, _) => m.CreatedAtUtc.AddDays(7));
```

```csharp [Membership tests] {4-5}
var created = new DateTimeOffset(2026, 1, 1, 0, 0, 0, TimeSpan.Zero);
await TestBiome.Start(out _)
    .Add(Blueprints.PendingInvitation, out var invitations,
        i => i.CreatedAtUtc = created,                // ExpiresAtUtc derived → Jan 8
        i => i.ExpiresAtUtc = created.AddDays(-1))    // explicit → kept
    .BuildAsync();
```

The same pattern from the library's own tests (`Membership/Domain.cs`): expiry derives **after** the customizer has changed the creation time.

```csharp [Membership/Domain.cs] {3}
internal static readonly Blueprint<MembershipSeed, PendingInvitation> Invitation = Blueprint
    .For<MembershipSeed, PendingInvitation>(ctx => new() { CreatedAt = ctx.Now })
    .Derive(i => i.ExpiresAt, (i, _) => i.CreatedAt.AddDays(7));
```

### What counts as "unset"

|Type|Unset means|
|---|---|
|reference types, `T?`|`null`|
|numbers, `bool`|`0`, `false`|
|`DateTimeOffset`|`default(DateTimeOffset)`|
|`string`|`null` only. **`""` counts as set.**|

::caution
An **empty string counts as an explicit value**, so leave sequence-managed or derived strings `null` in the factory. A `Derive` also cannot keep an explicit `null`. If a test needs one, ask for a base blueprint without that `Derive`.
::

For nullable value types the distinction holds too: `int?` `null` fills, but `0` survives.

## Derives run in order

`Derive`s run in **declaration order**. Derive a value from a sequence number *after* the sequence:

```csharp [Blueprints.cs] {2-3}
    .Derive(pr => pr.PullRequestNumber, PullRequestNumbers)
    .Derive(pr => pr.Title, (pr, _) => $"Pull request {pr.PullRequestNumber}")
    .Derive(pr => pr.Branch, (pr, _) => $"feature/{pr.PullRequestNumber}")
```

## Properties must be settable

::warning
A customizer cannot assign an `init` property (`CS8852`), so any property a test varies needs a `set`. If the model must stay `init`, write a blueprint factory method with optional named parameters, or ask the model's owner to make the property settable.
::

The property you select in `Derive` or `options.Default` must be a **directly writable instance property**, like `e => e.Name`. Anything else throws `ArgumentException` at declaration time.

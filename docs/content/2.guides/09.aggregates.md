## When one concept is several rows

Creating an organization may create an organization row, a root team, and a membership. Rather than three Adds, customize one small **input** object and build the rows from it. The result implements `IBiomeAggregate`, and **its parts are saved in place of the aggregate**.

::code-group

```csharp [With Biome] {13,15-16,25-26}
public sealed class OrganizationInput
{
    public string DisplayName { get; set; } = "Test Organization";
    public string? Slug { get; set; }
    public string Role { get; set; } = "owner";
    public bool IsDefaultMembership { get; set; }
}

public sealed record OrganizationGraph(
    Organization Organization,
    Team RootTeam,
    OrganizationMembership Membership
) : IBiomeAggregate
{
    public IEnumerable<object> GetEntities() =>
        [Organization, RootTeam, Membership]; // save order
}

public static partial class Blueprints
{
    public static readonly InputBlueprint<
        ZeeqSeed,
        OrganizationInput,
        OrganizationGraph
    > Organization = Blueprint
        .FromInput<ZeeqSeed, OrganizationInput, OrganizationGraph>(
            () => new(),
            (input, ctx) =>
            {
                var owner = ctx.Seed.Owner;
                var org = new Organization
                {
                    Id = ctx.NewId("org"),
                    DisplayName = input.DisplayName,
                    Slug = input.Slug,
                    CreatedByUserId = owner.Id,
                };
                var team = new Team
                {
                    Id = ctx.NewId("team"),
                    OrganizationId = org.Id,
                    IsRootTeam = true,
                };
                var membership = new OrganizationMembership
                {
                    Id = ctx.NewId("mem"),
                    OrganizationId = org.Id,
                    UserId = owner.Id,
                    Role = input.Role,
                    Status = MembershipStatus.Active,
                    IsDefault = input.IsDefaultMembership,
                    CreatedByUserId = owner.Id,
                };
                return new(org, team, membership);
            }
        )
        .Derive(i => i.Slug, (_, ctx) => ctx.NewId("org"));
}
```

```csharp [OrganizationTests.cs] {6-8}
await TestBiome
    .Start(_db, out _)
    .Add(
        Blueprints.Organization,
        out var orgs,
        o => o.IsDefaultMembership = true,
        o => o.Slug = "beta"
    )
    // saves org, root team, membership for each, in GetEntities() order
    .BuildAsync();
```

Customizers act on the **input** (`OrganizationInput`), not on the rows. `Derive` on an input blueprint also targets **input** properties, and runs before the build function.

## Expansion at save time

At `BuildAsync`, aggregates are expanded **recursively** into their parts. Duplicate references are saved once, and a cycle in `GetEntities()` throws. The library's `Membership` tests show the effect: the owner (seed row) precedes the organization and membership parts.

```csharp [MembershipTests.cs] {2-10}
await biome
    .AddOrganizations(
        out var graphs,
        input =>
        {
            input.Slug = "alpha";
            input.IsDefault = true;
        },
        input => input.Slug = "beta"
    )
    .BuildAsync();

// store.Entities: [owner, graphs[0].Organization, graphs[0].Membership,
// graphs[1].Organization, …]
// biome.All<OrganizationGraph>().Count == 2   (inspection keeps the wrapper)
```

::note
`All<T>()` and `Last<T>()` include **aggregate wrappers and transient entities**, but not seed rows. The store never receives the wrapper itself.
::

## Variants and transients

Input blueprints support `.With`, `.Derive` and `.AsTransient()` like entity blueprints:

```csharp [MembershipTests.cs] {5}
var variant = Blueprints
    .Organization.With(i => i.Slug = "trait")
    .With((i, ctx) => i.IsDefault = ctx.Seed.Owner.Id == "owner")
    .Derive(i => i.Slug, (_, _) => "fallback")
    .AsTransient(); // none of the aggregate's parts are saved
```

::caution
**Use input blueprints for aggregates only.** A single entity should be customized directly. Global [defaults](/guides/save-hooks-and-defaults) apply to the aggregate object itself, not to its parts.
::

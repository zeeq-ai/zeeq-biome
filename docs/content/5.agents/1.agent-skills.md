The repository ships two [Agent Skills](https://agentskills.io): folders with a `SKILL.md` (YAML frontmatter `name` and `description`) and optional `references/`. They tell a coding agent *how this library is meant to be used*, so generated tests stay terse and don't hit the usual mistakes.

|Skill|Use it when…|Source|
|---|---|---|
|`zeeq-biome-tests`|Writing, reading or fixing test setup: `TestBiome.Start(...)` chains, `AddX(out var x)` sugar, `.Under`, `.Transient()`, sequences, `FakeTimeProvider`. Also for compile errors or Biome exceptions in a test.|[`.agents/skills/zeeq-biome-tests`](https://github.com/zeeq-ai/zeeq-biome/tree/main/.agents/skills/zeeq-biome-tests)|
|`zeeq-biome-blueprints`|Creating or changing test infrastructure: the seed, `TestBiome`, blueprints, traits, `Derive`, sequences, the four sugar methods, scenario helpers, options, and EF Core wiring.|[`.agents/skills/zeeq-biome-blueprints`](https://github.com/zeeq-ai/zeeq-biome/tree/main/.agents/skills/zeeq-biome-blueprints)|

::tip
**Writing tests with existing sugar? Use `zeeq-biome-tests`.** Adding a new entity type, blueprint or option? Use `zeeq-biome-blueprints`. An agent that loads both can switch between them.
::

## What the skills teach

::code-group

```text [zeeq-biome-tests]
Reading a chain         every Add re-anchors; .Under jumps back; entities exist at once
Writing a chain         singular sugar, out _ for the unasserted, customize only the property under test
Comma vs plus           a comma is a new entity, + stacks traits on one entity
Fan-out                 children multiply per parent, flat array in parent order
Time                    never DateTimeOffset.UtcNow; share a FakeTimeProvider
Common mistakes         a table of compiler errors and runtime exceptions, with fixes
```

```text [zeeq-biome-blueprints]
Per entity type         one blueprint + four sugar one-liners (+ optional traits/helpers)
Factory rules           valid and uninteresting; ctx.NewId, ctx.Now; typed parent, ctx.Ancestor
Derive and sequences    fill-only; declare in order; PerParent / Per<T>; never ctx.Last for wiring
Variants and inputs     bp.With(trait); FromInput only for aggregates
Options                 SeedEntities, Default, BeforeSave/AfterSave, TimePrecision, Ids; EF store wiring
Mistakes to avoid       setting a derived property in the factory, index + 1 numbering, …
```

::

## Install them in your repository

Copy the two folders into the skills directory your agent reads. This repository keeps them in `.agents/skills/` and symlinks `.claude/skills` to it:

::code-group

```bash [Copy]
# From the root of your repository
git clone --depth 1 https://github.com/zeeq-ai/zeeq-biome /tmp/zeeq-biome
mkdir -p .agents/skills
cp -R /tmp/zeeq-biome/.agents/skills/zeeq-biome-tests .agents/skills/
cp -R /tmp/zeeq-biome/.agents/skills/zeeq-biome-blueprints .agents/skills/
```

```bash [Claude Code symlink] {3}
# Make Claude Code discover the same folder
mkdir -p .claude
ln -s ../.agents/skills .claude/skills
```

::

::note
Skill folders must keep their layout (`SKILL.md` plus `references/`), because each `SKILL.md` links to its references by relative path. Check your agent's documentation for where it loads skills from.
::

## Give agents the docs, too

Every page on this site can be handed to an agent as Markdown: use **Copy page** or **View as Markdown** at the top of any page. The site also publishes [`/llms.txt`](/llms.txt) and `/llms-full.txt` for tools that read them.

::tip
A good prompt is short: *"Read https://zeeq-ai.github.io/zeeq-biome/raw/guides/customizing.md, then rewrite this test's setup with Biome."* The skills cover the details, so the prompt doesn't have to.
::
